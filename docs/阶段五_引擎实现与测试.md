## 二、引擎的判定顺序（这条比代码本身重要）

1. **lock 未满足的选项不渲染** —— 玩家看不到，也就不会知道自己少了一个选择。
2. **deviation 只命中 `kind:"action"`** —— `branch` 永不被改写。这是设计纪律第一条：结局分支必须是玩家真的按下去的。
3. **silent 选项点了没反应** —— 停在原地，不跳转、不弹提示。
4. **正常跳转**，进入节点时把这些 flag 写进 `set`。
5. **节点带 `ending`** → 打出收尾血字 → 解锁结局 → `playthrough + 1` → 清空 `game_save`。

写反了任何一条，整场游戏的选择都会变成"假的"，玩家一旦察觉，恐怖就失效了。

## 三、场景切换的实现

- 每个节点带 `scene`（s0–s6）。引擎发现和上一个节点不同才切，同场景连续节点不重复切。
- 时序：**0ms 加 `is-wiping` → 260ms 换 `data-scene` → 560ms 移除**。擦除动画跑到一半才换调子，看起来才是"剪切"，不是"渐变"。
- 全篇实际切换 **18 次**（v1.0 剧本实测）。规范已从 ≤12 放宽到 ≤20，理由写进 `阶段四补充_场景主题与切换规范.md`：进出"带子画面"本身就是剪辑点。

## 四、跨周目的三层变化

| 层 | 存在哪 | 玩家能不能清 |
|---|---|---|
| 本轮进度（当前节点、flag） | `rewind.game_save` | 能（清掉 = 重来） |
| 通关次数、已解锁结局、历史 flag | `rewind.meta_save` | **不能**，只增不改 |
| 解锁规则 / 变体文本 | `data/meta.json`（只读） | 不是存档，是规则表 |

由此产生三个玩家能感觉到、但说不清的变化：
1. 标题：`倒带` → `请勿倒带` → `已倒带 N 次`。
2. 结局页多一行小字：`这一盘，我替你放完了。`
3. 终局多出第三个选项 `先把电视关掉`（`playthrough ≥ 1` 才存在），通向 E4。
4. 同一节点多一句变体（如 E1 的"我早就见过这一幕"、E3 的"这一集我好像看过"）。

## 六、已知取舍 / 待办

1. **两处 `deviation` 的 target 恰好等于它原本的 next**（`a3_02`→`a3_04`、`a6_05`→`a6_06`）。也就是说"错位"目前完全靠**文案说谎**实现（按钮写"关掉电视"，节点写"我往前走了一步"），引擎照样记录 `deviations`。以后想让玩家更明显地感到"选项被改写"，只需把 `deviation.target` 换成另一个节点，引擎不用动。
2. **打字机在后台上限会被系统节流**。浏览器窗口不可见时 `setTimeout` 最低 1s 起跳，一段字能拖到十几秒。这是浏览器行为，不是 Bug；真机上前台体验正常（实测单行约 1.5 秒）。
3. **未做 `data/bundle.js`**。双击 `index.html` 仍然读不到 JSON（CORS）。要支持双击，阶段六可以做一次打包（把三份 JSON 塞进 `window.__SCRIPT__`）。
4. **未做移动端适配**（按需求文档的"明确不做"清单）。
5. **未接入音频**：`assets/` 还是空的，等文字部分定稿后再讲。
