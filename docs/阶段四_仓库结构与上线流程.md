**为什么要这么分**：
- `css` 与 `js` 分离，是因为**特效是唯一的"画面"**，它必须能被独立调参；
- `data` 单独成层，是因为阶段五要**反复改剧情而不碰代码**——这是整个项目最重要的工程约定；
- `docs` 跟着仓库走，这样换电脑、换人接手都不丢上下文。

## 二、怎么把它跑起来（三种方式，按推荐排序）

### ① 本地服务器（推荐）
```powershell
cd "C:\Users\user\Doubao\chats\2026-11-16\new-chat-1\rewind"
python -m http.server 8000
```
然后打开 <http://localhost:8000/index.html>，点 **自检：读取 data/script.json**。
预期输出：`✅ 读取成功 / 剧本节点数：2 / 起始节点：demo_01`。

### ② VS Code + Live Server
装 `Live Server` 插件 → 右键 `index.html` → Open with Live Server。改 CSS 会自动刷新，适合调特效。

### ③ 直接双击 index.html
能打开、能看到 CRT 画面，但点自检会报 **CORS 错误**（`Failed to fetch`）。
**这不是 Bug**：浏览器禁止 `file://` 页面读取本地 JSON，这是安全策略。

> 关于"双击就能玩"：需求文档里写的是"双击可运行"，严格说这条路对**外置 JSON** 不成立。
> 阶段五有两个选择：
> - **A（推荐）**：坚持 `python -m http.server`，JSON 保持人类可读、GitHub 上能直接看；
> - **B**：阶段五顺手生成 `data/bundle.js`（把 JSON 包成 `window.__SCRIPT__`），双击即可玩，代价是每次改剧本要跑一次打包脚本。
> 我建议 A，只在最后发布版加 B。

## 三、推送到 GitHub（首次，逐步照做）

### 第 1 步：在 GitHub 上建空仓库
网页 → New repository → 名字 `rewind` → **不要勾 Add README / .gitignore / license**（勾了会和你本地的文件打架）。

### 第 2 步：本地已经初始化过，直接接远端
```powershell
cd "C:\Users\user\Doubao\chats\2026-11-16\new-chat-1\rewind"
git remote add origin https://github.com/<你的用户名>/rewind.git
git push -u origin main
```

### 第 3 步：以后每次改完
```powershell
git add -A
git commit -m "feat: 接入引擎与序章节点"
git push
```

### 如果 push 被拒
- `rejected (fetch first)`：远端有你本地没有的提交（通常是建仓时勾了 README）。
  先 `git pull --rebase origin main`，再 `git push`。**不要**直接 `push --force`。
- 要账号密码：GitHub 已不支持密码推送，用 **Personal Access Token**（Settings → Developer settings → Tokens，勾 `repo` 权限），把它当密码填。

## 四、Commit 规范（阶段六会正式用，这里先立起来）

格式：`类型: 一句话`

| 类型 | 用在 |
|---|---|
| `feat` | 新功能、新章节、新结局 |
| `fix` | 修 Bug（选项不响应、时间码错位、存档串轮） |
| `text` | 只改剧情文字/台词（不涉及代码） |
| `style` | 只改 CSS/特效参数 |
| `docs` | 只改文档 |
| `chore` | 结构、配置、初始化 |

好例子：`text: 第二幕把"这有什么好看的"提前，制造台词错序`
坏例子：`update`、`改了点东西`、`fix bug`

## 五、分支策略（阶段六展开，先留个念头）

```
main    ← 只放"能完整通关"的版本
 └ dev  ← 日常改 Bug、加剧情都在这
```
改完在 `dev` 自测 → 能通关 → 合并回 `main`。
好处：`main` 永远是"能给朋友玩"的状态，`dev` 里可以随便乱。

## 六、本阶段的已知取舍

1. **index.html 是自检页，不是游戏。** 这是故意的：阶段五会用真正的标题页替换它。
2. **js 三个文件是空壳，只有注释。** 里面写的"判定顺序"很关键——
   `branch` 类选项**永不**被 deviation 命中，这条顺序错了，整场游戏的选择都会被玩家判定为假的。
3. **assets 是空的。** 音频先不做，避免卡在素材授权上（见需求文档"明确不做"）。
4. **仓库名暂定 `rewind`。** 中文名《请勿倒带》，仓库用英文，符合 GitHub 习惯。
